# JGOLD adaptive learning engine v2

Status: implemented and released to the Expo `production` branch on 2026-08-28  
Android runtime: `1.5.0`  
Production update group: `a43c647e-5ebd-4141-ba6c-9fec529cd4bd`

## Product promise

JGOLD should answer four questions with evidence:

1. What can Jevan independently do?
2. Which prerequisite or practice angle is blocking the next ability?
3. What should he practise next for the greatest useful gain per minute?
4. Is the ability still retrievable and transferable after time has passed?

The app must not equate reading, confidence, familiarity, or immediate repetition with learning. It records observed performance and labels memory values as estimates.

## Methodology studied

### Math Academy

Primary source: <https://www.mathacademy.com/how-our-ai-works>

Implemented concepts:

- A prerequisite graph and learner-specific state over that graph.
- Frontier selection: locked nodes are excluded; ready, weak, and due nodes receive priority.
- Minimum-effective spaced review rather than constant repetition.
- Response speed, hints, misses, and delayed clean retrieval change the evidence value.
- Practice is selected for learning value, readiness, retention risk, and transfer gaps.
- The model distinguishes a prerequisite from an encompassed component skill. The v2 schema supports `prerequisite`, `encompasses`, and `confusable` edges; the UI currently exposes prerequisite edges first.
- Interleaving and discrimination are explicit practice angles rather than accidental side effects.

Important boundary: JGOLD does not claim to reproduce Math Academy's proprietary diagnostic or task-selection system. It applies the public methodological principles to a personal, multi-domain engine.

### Justin Skycak, Advice on Upskilling

Primary source: <https://www.justinmath.com/advice-on-upskilling/>

The phone's Kindle copy was inspected directly. Fifty-eight highlights and one personal note were extracted into `JGOLD-Advice-Upskilling-Highlights.json` in Android Downloads. The source-driven seed tree uses the following principles:

- Learning is improvement in a tangible, reproducible performance.
- Work backward through prerequisites and carry out granular learning bottom-up.
- Deliberate practice is a high-volume loop of attempt, feedback, adjustment, and retry at the edge of ability.
- Retrieve before consulting a reference; use references as minimal assistance.
- Consume only enough information to enable production.
- Build fundamentals in a scaffolded setting, then use projects for integration and transfer.
- Prefer short, frequent sessions and measurable progress.

The seed tree is curated, not generated by an unreviewed language-model guess. Every node stores source references and an inference-confidence value.

### Mochi

The installed Android app (`cards.mochi.app`) was inspected on-device. It was logged out and offline, with an empty inbox and no personal deck history available. Its useful product patterns were supplemented from official documentation:

- Cards combine Markdown notes, flashcards, links, backlinks, and review history.
- New-card learning is separated from scheduled review.
- Review uses simple remembered/forgot evidence and re-review for lapses.
- FSRS mode models per-card stability, difficulty, and target retention.
- Review history preserves timestamps, intervals, outcomes, and duration.

JGOLD keeps the simplicity and historical evidence but extends the unit of learning from a card to a measurable skill with prerequisites and transfer tests.

## Evidence model

Every custom skill is assigned one primary evidence angle:

- `conceptual`: explain the model, causal mechanism, or invariant.
- `procedural`: execute the procedure.
- `conditional`: choose when and why to use it.
- `discrimination`: distinguish it from plausible alternatives.
- `transfer`: use it in a changed or real-world context.

An attempt records:

- outcome: clean, helped, or missed;
- evidence angle;
- response latency;
- hint count;
- whether the context tests transfer;
- strength before and after;
- estimated retention before the attempt;
- timestamp.

A clean delayed retrieval expands stability more than an immediate repetition. A miss shortens stability. Hints reduce independent evidence. A clean transfer attempt receives additional transfer evidence. These are deterministic local rules and remain auditable.

## Storage

The encrypted on-device SQLite database now includes:

- skill-node dimension, source references, and inference confidence;
- stability, difficulty, due date, estimated retention, and per-dimension scores;
- append-only `skill_tree_attempts` evidence;
- typed `skill_tree_edges` for prerequisite, encompassment, and confusion relationships.

Migration id: `skill-trees-v2`. Existing trees and progress are preserved and receive safe defaults.

No source text, learning history, or statistics are sent to the existing cloud AI gateway. The source-grounded seed is assembled locally from the encrypted books and annotations tables.

## Adaptive selection

Locked nodes are never selected. Eligible nodes are ranked from:

- whether review is due;
- estimated retention risk;
- whether the node is on the active frontier;
- the gap in transfer evidence;
- the weakest evidence angle.

The score is intentionally inspectable. It is not a black-box claim of optimality.

## Statistics shown

Each custom tree reports:

- estimated current retention;
- abilities due for review;
- reliable and mastered abilities;
- clean-attempt rate;
- median response latency;
- independent-attempt rate;
- transfer success rate;
- net strength gained over 30 days;
- conceptual, procedural, conditional, discrimination, and transfer scores.

These statistics describe interaction evidence. They must never be labelled as direct measurements of neural change or long-term memory.

## Source-grounded seed

Learning → **Train how you learn** creates an idempotent ten-node tree named **Learning how to learn**. It covers:

1. defining a reproducible performance;
2. mapping prerequisites;
3. calibrating edge-of-ability practice;
4. retrieval before review;
5. tight correction loops;
6. minimum-effective spaced review;
7. discriminating between similar tools;
8. transfer through changed-context production;
9. crediting encompassed skills inside advanced work;
10. operating the complete evidence-driven system.

The tree cites matching Skycak highlights already present in JGOLD and labelled Math Academy summaries. Creating it twice returns the existing tree.

## Next safe expansions

These are not yet implemented and must not be represented as complete:

- a review-and-approve proposal screen for extracting arbitrary skill graphs from any selected book or note;
- diagnostic question compression and evidence propagation across postrequisites;
- explicit encompassment/confusable-edge editing in the UI;
- per-domain fitted scheduler parameters once enough personal evidence exists;
- richer charts for calibration, time-to-reliability, and transfer by domain;
- optional AI-assisted extraction using only passages the user explicitly selects and approves for cloud processing.

Do not silently infer and commit arbitrary skill graphs from private reading. Proposed nodes and edges need visible provenance, confidence, and user review because a confidently wrong prerequisite graph will train the wrong thing efficiently.
